# Git 范围与快照

先确认仓库、用户指定的路径范围及比较任务。使用 Git 只读命令取得文件内容，工作区和索引保持原样。

| 请求 | 旧侧 | 新侧 |
| --- | --- | --- |
| 检查本地修改（默认） | HEAD | 磁盘当前状态；包含范围内已暂存、未暂存、未跟踪表格 |
| 只检查暂存区 | HEAD | 索引中的内容 |
| 审查当前分支相对目标分支 | 两分支的共同祖先 | 当前分支提交，不包含工作区改动 |
| 明确比较两个版本 | 用户指定的旧版本 | 用户指定的新版本，直接比较两端 |

目标分支不明确时先询问，不猜测 `main` 或上游分支就是目标。一次任务先解析并固定提交 ID，避免处理过程中分支移动改变基准。没有 HEAD 的新仓库，将范围内文件作为新增，并说明没有历史基准。

## 收集文件

- 本地任务通过 `git diff --name-status -z --find-renames HEAD -- <范围>` 收集已跟踪文件，再通过 `git ls-files --others --exclude-standard -z -- <范围>` 加入未跟踪文件并去重。暂存与未暂存改动比较的是 HEAD 到当前最终内容。
- 暂存区任务使用 `git diff --cached --name-status -z --find-renames HEAD -- <范围>`，新侧读取索引，不用磁盘内容代替。
- 两版本任务使用 `git diff --name-status -z --find-renames <旧提交> <新提交> -- <范围>`。分支审查先取得共同祖先，再执行这个比较。
- 按 NUL 分隔处理状态和路径，支持空格、中文及换行文件名。改名取旧、新各自的路径；新增和删除保留明确的空侧。
- 只读任务范围内的 CSV/XLSX。每份文件的结果应能对应原仓库路径；跨 CSV/XLSX 改名、内容缺失等无法比较的项目列明原因。

## 准备双侧输入

通过 `git cat-file blob <提交>:<路径>` 或 `git cat-file blob :<路径>` 读取版本或索引的原始字节。使用二进制安全的文件写入，尤其是 XLSX；避免经过会解码、重编码的文本管道或旧版 PowerShell 重定向。

快照保留 `.csv` 或 `.xlsx` 后缀。明确不存在的一侧使用空文件，或平台空设备；读取历史失败不等于该文件不存在。磁盘侧取文件当前字节，不重算或重存工作簿。

若读取内容以 Git LFS 指针头 `version https://git-lfs.github.com/spec/v1` 开始，它还不是表格。通过仓库现有 Git LFS 能力取得指针对应的真实对象；若对象缺失、无访问权限或无法取回，报告该文件比较失败，不把指针或空文件当作真实内容。

每份表格调用一次包内 CLI，单独保存报告。完成后列出成功、失败、跳过的文件及实际基线，只有全部目标文件成功比较后才能对整个范围作完整结论。
