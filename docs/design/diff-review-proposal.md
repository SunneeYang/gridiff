# Gridiff 差异审查页面改进方案

> 本文件记录原型阶段；后续正式页面接入与验证见[正式差异页面接入](production-integration.md)。
日期：2026-11-06。基线：`main@f781946`。交付范围：方案与[可交互原型](diff-review-prototype.html)，未修改正式页面、比较引擎、CLI 或安装包。

后续请求已补充[四套组件风格](style-design.md)与[五套浅深配色](theme-design.md)，组件风格、阅读布局和配色在同一个原型中独立切换。下文的布局测量来自首轮信息架构原型，不包括外部设计评审控制区，也不代表四种新布局的尺寸。

## 建议与使用场景

保留“在原表语境中读懂差异”这个核心，优先整理信息层级和操作顺序。页面应帮助策划与程序完成：**确认比较对象 → 看清变化范围 → 定位相关记录 → 核对旧新值**。

例如，用户原本只想确认药水涨价是否正确。打开演示表后，先看见“旧版本 / 新版本”，再看见当前表的记录变化与“删除字段 1”。选择“售卖价格”可以集中核对价格，但统计与字段删除提示仍在，避免误以为筛选后的内容就是全部变化。原型不把其他改动自动判为错误；“是否符合预期”仍需业务上下文。

**先试原型：**

1. 在“字段”中选择“售卖价格”。结果包含两条价格修改、一条新增、一条删除，共四条；当前表总量不随筛选变化。
2. 点击“下一条 / 上一条”连续定位，或切换“变更清单”比较字段、旧值、新值。
3. 搜索一个不存在的名称，再点击“清除筛选”恢复。
4. 切换“掉落表”，验证当前工作表的统计；取消“仅含变化记录”，可查看未变化记录。
5. 在页面下方切换长文本、读取中、读取失败或没有差异。这是原型演示控制，不属于正式产品流程。

## 已核实的现状

检查了当前源码、当前构建产物匹配情况，并启动原生 CLI 的真实浏览器页面。数据采用仓库 `test/fixtures/before.csv`、`after.csv` 生成的 XLSX，以及额外构造的“掉落表”。这些是演示数据，不是实际业务审查结论。

两次独立评估分别负责无检测器的交互审查，以及静态检测、DOM 尺寸、键盘和颜色检查；先阅读前者，再合并后者。

| 问题 | 当前证据 | 用户受到的影响 |
| --- | --- | --- |
| 比较对象不够明确 | 旧新路径共用 11px 单行，最大宽 760px；桌面上新路径尾部被截断。`media/main.css:51`、`media/main.js:205` | 需要悬停或猜测“哪个是旧、哪个是新”。窄屏的来源行还会溢出自身布局。 |
| 表格可视区域偏小 | CSS viewport 1366×768 时，内容从 y=386.5 开始，高 325.5px；表头约 85px，首屏仅完整显示两条记录 | 外观、解析设置、说明和统计占用了持续审查所需空间。 |
| 清单拉开短值 | 第一条生命药水记录高约 405px；40 与 60 的文字起点相隔约 543px。`media/main.css:106`、`:113` | 简单数值需要较大的眼动和滚动。 |

| 字段筛选名称偏窄 | “仅看变动字段”实际上保留新增记录非空字段与修改字段的并集。`src/page.js:18` | 用户可能以为勾选后只能看到直接修改过的字段。 |

现有产品已有固定表头/记录列、原表顺序、旧新文字、字符级标记、原生表格语义、可见焦点和键盘横向滚动。采样的默认浅深主题关键文字对比度均达到 4.5:1；没有依据声称当前产品缺少基本可访问性。此次应保留这些能力。

## 改进设计

| 优先级 | 改动 | 为什么这样安排 | 原型覆盖 |
| --- | --- | --- | --- |
| P1 | 分开显示旧、新文件名，完整来源可展开 | 比较依据是审查开始前必须确认的信息；不能仅依赖悬停 | 两个来源标签，来源与设置展开 |
| P1 | 将低频外观/解析设置移入次级入口 | 把持续审查的空间留给表格；设置入口仍可发现 | 原型实现外观，格式/主键编辑仅说明保留 |
| P1 | 一行紧凑统计，注明“当前表全部变化”；结果区独立显示筛选后的记录数 | 区分工作簿读取范围、当前工作表总量和当前结果 | 全表统计、仅字段变化计数、结果数、筛选说明 |
| P1 | 字段结构变化说实际发生了什么 | “删除字段 1：是否贵重”比列出所有可能类别更直接 | 可展开字段删除说明，筛选时仍可见 |
| P1 | 压缩表头和记录间距，按数据类型分配列宽 | 编号、品质不需要和描述字段一样宽；完整旧新值不能为密度让路 | 固定表头/记录列，数值对齐，12px 旧新标签 |
| P2 | 清单改为记录分组下的“字段 / 旧值 / 新值”行 | 短值相邻，长值行内展开，不新增重复的详情侧栏 | 清单最大宽 840px，长中文展开 |
| P2 | 增加明确的单字段筛选与记录定位 | 支持“先检查价格”的真实任务；筛选不能隐藏全表范围提示 | 字段筛选、前后定位、空结果恢复 |

原表对照仍是默认视图。列表用于连续读改动和长内容。原型保留 id/name 原字段，不为省空间擅自改变字段集合算法或删除重复信息。

原型的“字段”选择器是**新增的单字段查询概念**：选中后同时限定列与涉及记录，包含该字段的新增/删除记录。它不等价于当前“仅看变动字段”开关。正式实现必须保留当前并集规则，并将“显示列范围”和“按指定字段筛选记录”分开建模、明确命名。

## 视觉规则与 StyleKit 依据

选择 **StyleKit 的 GitHub Style 为一套主规则**，只吸收 Data Dense 的表格扫描方式与 Notion Style 的稳定阅读交互，不混用三套配色。来源固定在 [AnxForever/stylekit@a979db1c4690988f7d718e1dd1c1a251ebc97941](https://github.com/AnxForever/stylekit/tree/a979db1c4690988f7d718e1dd1c1a251ebc97941) 的 `dev` 提交，2026-11-04。它是第三方设计参考，不是 GitHub/Notion 官方规范；没有核实在线站点与该源码完全一致。

- [GitHub Style 规格](https://github.com/AnxForever/stylekit/blob/a979db1c4690988f7d718e1dd1c1a251ebc97941/lib/design-spec/samples/github-style.ts)：中性纸面、1px 边界、6px 圆角、4px 间距基准，14px 正文与 12–13px 辅助文字。蓝色用于操作/焦点，绿红用于新增删除，琥珀色用于修改。
- [Data Dense 规格](https://github.com/AnxForever/stylekit/blob/a979db1c4690988f7d718e1dd1c1a251ebc97941/lib/design-spec/samples/data-dense.ts)：数值右对齐、编号等宽、稳定的行列扫描。不采用 KPI 卡片、10px 中文标签，也不照搬与行高/内边距矛盾的 28px 行高。
- [Notion Style 规格](https://github.com/AnxForever/stylekit/blob/a979db1c4690988f7d718e1dd1c1a251ebc97941/lib/design-spec/samples/notion-style.ts)：系统中文字体、悬停仅改变背景、长值就地展开。不引入文档窄栏、米色主题或悬停缩放。

设计判断：配置审查的自然语言是工作表、主键、记录、字段、快照、版本、结构变化。白色表面、灰色网格、灰色未改值、绿色新值、红色旧值、琥珀色修改与蓝色焦点都有对应语义。特色仍是**同一原表上下文里的旧新值**，落实在版本来源、单元格、字段结构、清单列头与记录导航中。

不采用三种常见模板：大数字仪表盘、常驻详情侧栏、只靠红绿表达变化。层级通过位置、字号、字重和空间建立；表格用细边界，无装饰阴影。正文使用系统中文字体；仅编号、字段标识和数字使用等宽字体。控制目标至少 44px，表格数据保持紧凑，长文本自然增高。

StyleKit 三份规格主要是浅色规则，其通用深色生成器不等于经过验证的产品深色系统。当前原型外层跟随宿主，产品样本区采用五套分别设计的浅深色；“跟随系统”只决定明暗。正式页面继续区分浏览器与 VS Code 的主题路径，不将原型的宿主 CSS 变量直接搬进产品。

## 实现边界与最小落地顺序

第一批以展示层调整为主：`src/page.js` 信息结构，`media/main.css` 密度与清单排版，`media/main.js` 来源/统计/结构变化文案，必要的 `media/themes.css` 角色映射。保持比较结果、记录顺序、元数据展示与现有行为。

第二批再做单字段筛选和跨结果导航。原型只有固定小样本与单页数据；正式实现需要把过滤、分页、稳定记录标识与总量口径传到 native Go projection 和独立 VS Code JS view 两端，不能只在当前 DOM 页过滤后宣称已查完全部差异。需验证新增/删除字段、仅结构变化记录、跨页筛选/定位、复合键、重复键/无键记录与大数据量。

保持以下现有约束：

- 当前源码的第一个输入是旧版本，第二个输入是新版本。展示方向不能依据过时历史备注反转。
- 浏览器“重新计算”使用已捕获的只读快照；VS Code“重新读取”才会重读源文件。原型的状态模拟不等于这两条路径已实现。
- CLI 默认 XLSX 第一张表，插件默认全部；工作表选择只能切换已载入范围。若需要其他表，应重新发起更大范围的读取。
- Git 标签、commit 信息只有来源提供时才展示；只收到文件路径时，不推断 `HEAD`、分支或工作区状态。
- 外观、配色、交换左右、重新计算/读取、格式、主键、插件文本对比与结束比较均需在正式实现中保留。原型没接入这些操作，不表示删除需求。
- 定位、滚动不产生“已审查”状态；结束比较也不表示批准提交。不增加审批、评论、持久化审查进度或文件写入。

历史依据：已读取 `ddcc50e`、`b8db802` 完整提交说明，并结合当前代码核实原生比较与独立插件、Fork 临时输入快照和工作表范围约束。提交说明用于解释设计限制，不作为新的执行授权。

## 验证记录

- 当前产品：原表/清单切换、工作表切换、搜索零结果及恢复、字段开关、主键设置退出、焦点与键盘横向滚动；1366×768、1440×900 与 390×844 观察。未进行正式可用性实验。
- 原型：使用 T3 内联预览检查浅深主题与桌面/窄屏，使用独立空白浏览器标签运行交互；未启动原型 Web 服务。
- 同为 1366×768 CSS viewport，原型表格起点 y=273.5，比现状 y=386.5 提前 113px；内容区域高 456px，现状为 325.5px。该结果来自演示样本，不代表大表性能提升。
- 原型数据断言：仅字段变化记录保留；价格 4 条、品质 3 条；旧值可搜索；零匹配；掉落表变化/全量切换；无差异状态；HTML 转义。
- 原型浏览器复核：首条到末条再回首条，表格/清单定位均不被固定表头遮挡。390px 窄屏选择价格后，内容 `clientWidth = scrollWidth = 341px`；长中文可展开且不溢出单元格。编号换行与单字段列宽问题已修正。
- 状态检查：读取中隐藏结果并禁用数据控件；失败信息提供返回路径；空结果可清除筛选；长文本按需展开。所有演示状态均明确标注，不模拟网络成功或实际文件读取。
- Hallmark 静态检查：0 FAIL、0 REFLEX、0 WARN。其 `--render` 子阶段因未安装 `puppeteer-core` 未运行；视觉检查由 T3 渲染和浏览器完成，不能说该渲染检测已通过。
- Impeccable 静态扫描：当前两个 JS 源文件为 0 项，但仅为 regex 扫描。原型提示主题对比度、紧凑排版与标题层级；静态扫描混配深色文字和浅色背景，不能替代实际主题验证。紧凑标题层级按 Operate 模式保留；统计行的文字本身有内边距，不因容器边界提示重复加空白。
- 原页面的检测器叠层被现有 CSP 拒绝；没有弱化 CSP。采用源码、实际 DOM、截图与计算颜色补充证据。
- 内联宿主主题的采样：浅色主要文字、修改/新增/删除文字均高于 4.5:1，辅助文字为 4.71:1，表头辅助文字为 4.62:1；深色辅助文字为 5.08:1。发现浅色有底色的“不存在”原为 4.21:1，已改用正文颜色。此处是关键文字采样，不是完整可访问性认证。

此原型不是生产补丁，也不验证 Go/插件行为、真实大表性能、跨页导航、屏幕阅读器、所有主题配色或实体触屏。其作用是让信息层级和操作路线可以直接试用、讨论，再决定正式实现范围。

长文本标记沿用当前实现的共同前缀/后缀算法：同时修改开头并追加结尾时，中间未改段落也可能被标记。它不能被描述为精确的全文字符 diff；本次没有更换算法。
