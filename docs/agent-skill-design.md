# Agent 表格比较技能设计

状态：已实现，通过双轴审查和 macOS ARM64 本机验收。本文保留已确认目标、设计时基线与实现约定。

## 已确认目标

- 第一优先级是让 agent 直接读取准确的表格差异，再结合项目上下文解释变化。
- 首个验收场景：用户要求“检查这次装备表是否只改了价格”，agent 能列出价格变化并指出其他改动；变化应定位到表、记录和字段，并保留旧值与新值。
- 面向不同本地 agent 的通用技能，保留 Mova 配置表优势，不依赖用户个人项目或本机绝对路径。
- CLI 的机器输出直接复用现有 Go 比较核心，不依赖网页会话；技能负责准备输入、调用与解释。网页继续承担人工审阅展示。
- 输入场景包括两份文件、工作区相对 HEAD 的变化，以及两个提交或分支之间的变化。由 agent 使用 Git 准备文件快照，Gridiff 专注表格比较。
- XLSX 默认只读首表，与现有独立程序逻辑一致；需要其他范围时明确指定，并在结果中说明实际比较范围。
- 首个完整验收环境为 Codex，技能说明保持通用。
- CLI 支持将完整比较报告写入调用者指定的文件；大量差异由 agent 使用文件读取工具按需读取，无需另设大结果分页查询接口。
- 比较设置通过 CLI 参数公开；agent 可以调用已有参数，有实际需求时补充缺少的参数。
- 技能与同版本 CLI 可执行程序一起打包，用户安装技能即获得 CLI，无需另外安装。
- 用户要求审查配置改动时，agent 主动比较指定范围内所有 CSV/XLSX，无需点名 Gridiff，并列出失败、跳过的文件。
- 未指定版本时，本地修改比较 HEAD 与磁盘当前状态，包含范围内的暂存、未暂存和未跟踪表格；分支审查比较目标分支的共同祖先与当前分支；明确给出两个版本时直接比较两端。目标分支不明确时先确认。

## 设计时实现基线（01a43d1）

- 常规 CLI 使用旧文件、新文件顺序，启动或复用本地比较服务并输出网页地址；`--no-open` 只抑制打开浏览器，不输出差异报告。这是当前面向人工审阅的命令入口行为，不是比较能力依赖网页。见 [cli/main.go](../cli/main.go)。
- Go 核心已有完整的内存比较模型，计算本身不依赖网页。模型包含记录、单元格前后值、结构变化、统计和对齐信息。见 [cli/native.go](../cli/native.go) 与 [cli/native_model.go](../cli/native_model.go)。
- 网页响应按当前工作表、当前页和可见字段裁剪，不能直接当作完整差异报告；解析或某张表比较失败也需要独立判断。见 [cli/native.go](../cli/native.go) 与 [cli/native_table.go](../cli/native_table.go)。
- 独立程序的 XLSX 默认读取首表；插件默认读取全部表。公式仅比较文件保存的结果，不重算公式。见 [使用与配置](USAGE.md)。

## 实现约定

以下接口与验收范围已整体确认。

### CLI 与报告

```sh
gridiff --output <报告.json> <旧文件.xlsx> <新文件.xlsx>
```

- 指定输出文件时直接计算并写入 JSON 报告，不启动比较服务或浏览器；原有人工审阅入口继续使用。
- 报告包含版本、比较状态、实际工作表范围、格式与主键、全量差异统计、记录与字段变化，以及诊断信息。统计放在详情之前，便于先读概览。
- 完整性针对所选比较范围：默认首表，未选中的表不属于本次结论。报告保留所选范围内的全部差异，不套用网页的页码、搜索或可见列裁剪。
- 单元格保留旧值、新值及必要的类型和原始值信息；新增、删除、修改、结构及顺序变化沿用现有比较语义。
- 复用已有 `--sheets`、`--sheet`；公开格式、主键和自定义表头设置，具体参数命名随实现沿用现有概念，不另加技能专用配置系统。
- 比较失败与无变化是不同状态。失败时返回非零退出码和明确诊断，不能将部分结果描述为完整；成功发现差异仍视为一次成功的比较调用。
- 写报告不得覆盖输入表格；完整写入成功后才替换目标报告，避免中途失败留下看似完整的文件。报告路径及保留期限由调用者决定。

### 技能与分发

- 技能说明覆盖识别任务、准备双侧文件、调用 CLI、读取报告及结合项目上下文解释结果。
- 沿用现有五个系统/架构目标，按平台生成技能包，每包包含技能说明、同版本本平台 CLI、许可证及构建清单。技能通过包内相对路径调用 CLI，不依赖个人路径或全局 PATH。
- agent 在有依据时通过 CLI 参数调整比较方式；实际采用的参数出现在报告中，便于复核。审查配置改动时主动覆盖用户指定范围内的 CSV/XLSX，并列明成功、失败和跳过项。
- Git 版本读取保持旧、新方向，不切换用户分支、不改写工作区或索引；快照保留 CSV/XLSX 后缀，新增或删除文件使用明确的空侧。
- 默认本地审查比较 HEAD 与磁盘当前状态，已暂存、未暂存改动按当前最终状态合并比较，范围内未跟踪表格视为新增。用户明确只看暂存区或其他范围时，按其指定准备快照。
- 默认分支审查使用目标分支与当前分支的共同祖先作为旧侧、当前分支提交作为新侧；明确比较两个版本时直接比较两端。没有明确目标分支时先确认，不擅自选择基线。
- Git LFS 指针、无法取得的版本内容及无法解析的文件必须显式报告，不能当作空表或无变化。

### 验收范围

- 普通 CSV、Mova 四行表头、Mova 竖表及 XLSX 的实际变更，可定位到记录和字段并读到旧、新值。
- 大量差异完整写入报告，文件读取可覆盖全部变更，报告统计与实际变更一致。
- XLSX 默认首表，显式全部表或指定表时报告范围正确。
- 参数覆盖、无变化、解析或主键失败，以及输出写入失败均有明确结果；输入文件保持只读。
- 技能安装包内的 CLI 可直接运行；Codex 完成两文件比较和 Git 变更审查的真实调用。
- Git 场景覆盖暂存与未暂存混合改动、范围内未跟踪表格、文件新增删除，以及分支共同祖先与明确两版本比较的基线差别。
- 按改动范围验证原有网页入口，避免机器输出分支影响现有 Fork 使用方式。

## 验收结果

- 103 项 Node 单元测试、语法检查、Go vet 与全量 Go race 测试通过。
- 24 组原生 Go/插件等价场景及现有独立程序网页入口实测通过。
- 从技能 ZIP 解包后，包内 CLI 在受限 PATH 中完成 2 万条修改的完整报告、XLSX 首表/全部表、公式缓存、无变化、部分表失败及输入保护验证。
- 两个独立 Codex 实际按技能完成本地整体/暂存区审查，以及分支共同祖先/明确两端比较；正确识别额外字段修改、新增未跟踪表和删除表，并区分暂存值与磁盘当前值。
- 规范与需求两项独立审查均无待处理发现。五个平台完成交叉构建；只有 macOS ARM64 完成实机验收，其他平台尚未实测。本次不涉及插件市场发布。
